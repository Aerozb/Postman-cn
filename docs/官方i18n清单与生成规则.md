# 官方 i18n 清单与生成规则

> `AGENTS.md` 规则 15 的正文。**升级 Postman 新版本、批量补词条、改 `RULES` 生成规则区之前必须读完本文件。**
> AGENTS.md 里只留了三条一句话就能说完的静默失效陷阱，操作步骤和管线全在这里。

## 1. 取材路径

Postman 自己用 i18next 做多语言，`en-US` 资源包是第四条、也是最权威的取材路径——每一条都是官方登记为「需要翻译」的界面文案，不是启发式猜的（另外三条见 `AGENTS.md` 第 5A 节的对照表）。

**资源包的 URL 形态会随版本变，动手前必须自己实测确认，别照抄本文件的示例。** 12.27.5 实测（2026-09-11）当前形态是：

```
https://desktop.postman.com/i18n/locales/en-US/<namespace>.json
```

这个形态**不带内容哈希**，命名空间就是文件名（`common`、`request`、`collection`、`app-header`、`vault`…，12.27.5 上共 12 个）。

更早的版本用过 `https://desktop.postman.com/_ar-assets/locales/en-US/<namespace>-<hash>.json`（带哈希）。**这条在 12.27.5 上已经失效**：从页面 fetch 返回 404，磁盘缓存里 `_ar-assets` 也零命中，而 `i18n/locales` 有 22 条命中。所以「URL 带内容哈希、每次发版都换」这个旧说法现在也不适用了——升级后第一件事是重新确认路径形态本身。

确定当前形态最可靠的办法是**从磁盘缓存里挖真实 URL**：缓存记录的是 Postman 实际请求过的地址，不会骗人。遍历 `%APPDATA%\Postman\Partitions\*\Cache\Cache_Data`，把形如 `locales/<lng>/` 的 URL 全部捞出来（gzip/brotli 都要解）。

**每次动这批文案前都要重新抓，不能用 `_generated` 里现成的 JSON。** 那个目录是可再生产物、随时会被清理（本文件早先列过 `probe-i18n-assets.js`、`fetch-i18n-en.js`、`diff-i18n.js`、`batch-i18n.js`、`probe-i18n-rules.js` 五个脚本名和 `i18n-skip.json`，2026-09-11 核查时**全部已不存在**，别再照抄脚本名）；即使文件还在，隔一个版本也过期。12.24 → 12.25.7 之间清单从 12602 条涨到 13292 条，新增 348 条全是新功能文案（JDBC 数据源、组织迁移…），拿旧快照会整块漏掉。

抓取步骤（前两步是为了让 Postman 把当前 locale 包写进磁盘缓存，顺序不能换）：

```powershell
.\postman-zh.bat install    # 1. 打补丁并启动（install 会自己重启 Postman）
# 2. 让它跑十几秒，界面加载时自动拉取 locale 资源包
```

然后做三件事，一次性脚本写在 `_generated` 里就行，别当成项目固定入口：

1. **挖 URL 确认形态**：按上面说的遍历磁盘缓存，同时得到命名空间清单。
2. **拉清单**：**必须从 Postman 页面里 `fetch`**（走 CDP `Runtime.evaluate`）。这样是同源请求，不受 CORS 限制；直接在 Node 里 `fetch` 那个域会被挡。官方包是多层嵌套 JSON，展平（键用 `.` 连接）后去重。
3. **筛真实漏翻**：把每条原文过一遍 `payload/zh-localize.js` 的 `translate()`，只留翻不出中文的。**这一步绝不能省**——12.27.5 实测 1789 条纯文本候选**全部**已有译文，真实漏翻 0 条。把候选直接当漏翻去翻，会白做大量工作，还可能用更差的译文覆盖既有词条。

含插值的那批同样要先测再动：12.27.5 上 412 条含插值文案，用实际值展开后**全部**已被现有 `RULES` 覆盖。

确认自己拿的是新清单而不是旧快照：抓取前先备份上一份，抓取后比条数和新增文案。

## 2. 三条静默失效陷阱（AGENTS.md 规则 15 已摘要）

写词条时有两个坑会让词条**静默失效**（合并成功、`rg` 也能查到，但运行时永远命中不了）：

- **键必须是 `normalize()` 之后的形态**。`translate()` 先 `normalize()`（去零宽字符、`&nbsp;`→空格、**连续空白压成单个空格**、`trim()`）再查 `EXACT`。所以官方原文里带首尾空格的（`"Parse Error: "`）或带换行的多段文案，键都要写成去首尾空白、换行压成空格的形式；输出的首尾空白由 `preserveOuter` 自动补回。

  `合并译文.js` 自 2026-09-01 起在入口就把键归一（并打印"已把 N 条译文的键归一"），所以走合并流程的批量词条不会再踩这个坑；**手工直接编辑 `payload/zh-localize.js` 时没有这层保护**。判断存量有没有死词条：只扫 `EXACT` 区间，把每个键和它 `replace(/\s+/g," ").trim()` 的结果比对，不等就是永远匹配不上的死词条。当时查出 34 条，其中 29 条另有活词条覆盖（无害重复），2 条真需要补规范化形态，3 条是授权页刻意按"缺字母 s"渲染形态写的（payload 里另有 `\bPo\s+tman\b` 一类清理规则印证这个现象），**不要去"修正"那 3 条**。
- **`合并译文.js` 会拒收不含中文的译文**。像 `"SCIM API keys": "SCIM API Key"` 这种全英文的值会被静默丢弃，得给出含中文的写法（`"SCIM API 密钥"`）。

第三条：含 `{count}` 这类单花括号插值的官方文案（约 1300 条）**不能进 `EXACT`**——运行时 DOM 里出现的是填好值的结果，原串永远不会出现，必须写 `RULES`。

**合并去重使用词典对象的真实键**（2026-09-07）：切出 `EXACT` 后在独立 VM 中只求值这个对象字面量，再用 `Object.keys()` 取键。旧的引号正则会从前一个译文的尾引号跨行匹配，漏掉以冒号开头的完整句（例如 `: Native Git support is only available on the Desktop App.`），导致每次合并都重复插入。合并后再次运行 `merge --check` 应报告没有新增；冒号、撇号、转义引号等都应保持幂等。

## 3. 生成规则管线

含插值那批已用一条生成管线做完，工具在 `_generated`。**这批脚本都是一次性产物，不是常驻入口，可能已被清掉，用前先确认存在**（`_generated` 按约定可被随时删除，也不要把它们固化进 `scripts/`）：

| 脚本 | 作用 |
|---|---|
| `rules-skeletons.js` | 把官方文案的 ICU plural/select 展开成「运行时真正出现的骨架」，只留下现有词典还翻不出的；`rules-skip.json` / `rules-rejected.json` 里的骨架会跳过 |
| `rules-compile.js` | 把「骨架 → 中文模板」编译成 `[正则, 替换]`，含四项自检（填样例必须命中、译文必须含中文、不得命中常见短串、名称插值不得过宽） |
| `gen-rules-b*.js` | 逐批手写的翻译表，输出 `rules-b*.json` |
| `merge-rules.js` | 用一对 `BEGIN/END` 哨兵注释整块重写 payload 里的生成规则区，幂等 |
| `regress-i18n.js` | 全量语料回归：列出「丢了中文」和「新增半截」的条目。重建做法与语料来源见 [升级与发布.md](./升级与发布.md) 第 2 节 |

写生成规则时踩过四个坑，都由上面的自检/回归兜住了，改这块前务必理解：

- **生成规则要插在 RULES 头部**。手写规则里有 `^Delete (.+)$`、`^Copy (.+)$` 这种通用动词兜底，排在前面会把具体规则整个吃掉。具体优先于通用。
- **同一块内也要按具体度排序**：先比骨架里的字面量字符数，相同再让「实体名候选列表」型规则优先。否则 `^Delete (.+?)\?$` 会抢在 `^Delete (环境|集合|…)\?$` 前面，把 `Delete environment?` 只翻出半截。
- **名称插值贴在句首最危险**：`^(名称) workspace$` 会把 `Share workspace` 变成「Share 工作区」。所以要求句首名称插值的字面量至少两个英文单词（或 ≥12 个非空白字符），句尾的至少 6 个字符；不达标的骨架直接拒收并记进 `rules-rejected.json`。
- **实体名/类型名插值必须走 `i18nTerm()`**（payload 里的辅助函数 + `I18N_TERMS` 词表）。做法是把已知实体名的候选列表直接编进正则，这样输入不是实体名时规则根本不命中、会继续往后走手写兜底，而不是被吃掉后返回英文。

每次 `merge-rules.js` 之后都要跑一遍全量语料回归，指标是「新增半截 = 0」；仍需人工判断的骨架清单见 `rules-skeletons.txt`。
