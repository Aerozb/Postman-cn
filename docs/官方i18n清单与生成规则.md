# 官方 i18n 清单与生成规则

批量补词条或修改生成 RULES 前阅读本文。官方资源提供原文，实际翻译仍由运行时 payload 完成；用户截图反馈的修复流程见 [维护指南](./维护指南.md)。

## 1. 获取当前资源

官方 `en-US` 资源是重要语料，但 URL 形态、命名空间和内容都会变化。历史上既有带哈希的 `/_ar-assets/locales/en-US/…`，也有不带哈希的 `/i18n/locales/en-US/<namespace>.json`；以当前 Postman 的实际请求为准。

1. 通过统一入口启动已安装的 Postman，等待界面加载。无需为抓资源反复重装。
2. 从当前页面资源或 `%APPDATA%/Postman/Partitions/*/Cache/Cache_Data` 找出实际 `locales/<语言>/` URL，确认命名空间。缓存可能经过 gzip/brotli 压缩。
3. 重新拉取本轮资源并记录来源、时间和版本。优先从 Postman 页面经 CDP 执行同源 fetch，复用应用的网络环境；外部请求失败时应检查网络或服务端访问条件，别归因于 Node 的浏览器 CORS 限制。
4. 展平嵌套 JSON、去重，将每条原文先过权威 payload 的 `translate()`，再人工筛选。含插值的文案先用代表值展开，测试既有 RULES，避免重复翻译已有内容。

旧 `_generated` 快照可用于差异比较，不作为本轮唯一语料。抓取和临时生成脚本也放 `_generated`，运行前确认文件存在；本文不约定不存在的临时脚本名。

## 2. 入库与查重

- **键与 `normalize()` 一致**：去零宽字符、NBSP 转空格、连续空白压成一个空格、trim。首尾空白由翻译器保留。合并工具直接复用运行时归一函数，手改词典也要守住该形态。
- **撇号独立处理**：直撇号与弯撇号未被归一，按真实原文补变体；NBSP 已被归一，另存该变体没有收益。
- **译文须含中文**：全英文值会被合并工具过滤，例如写“SCIM API 密钥”，而不是另一份全英文短语。
- **插值进入 RULES**：官方 `{count}` 等模板填值后才进入 DOM，固定模板原串不应作为 EXACT 词条。注意与界面上刻意展示的变量语法区分。
- **按最终 EXACT 查重**：共享汉化沙箱执行 payload 初始化，覆盖初始对象及后续 `Object.assign`；统计也包含追加的 PHRASES 和正则。术语表、菜单表等同名键保持独立。

合并在内存中验证新源码和译文回读后写盘，头部插入保持人工后写优先。再次 `merge --check` 应无重复新增，冒号、引号和转义字符同样保持幂等。

## 3. 生成插值规则

临时生成流程按职责组织，无需保留某次批处理的脚本文件名：

1. 展开 ICU plural/select，得到实际会渲染的句式骨架。
2. 用代表值测试既有翻译，仅保留未覆盖的骨架；记录明确跳过和需复核的情况。
3. 将“骨架 → 中文模板”编译为 `[正则, 替换]`。自检：样例必须命中、结果含中文、常见短串不误命中、名称插值范围受控。
4. 按 payload 中 BEGIN/END 哨兵替换生成区，保持重复执行幂等，禁止未经排序地追加到通用动词规则之后。
5. 对比改前、改后的完整语料结果，确认没有丢失已有中文或新增半译。

必须保留的排序与匹配约束：

- 具体规则排在 `^Delete (.+)$`、`^Copy (.+)$` 等通用规则之前。
- 同一生成区按字面量具体度排序；字面量相同时，实体类型限定规则优先于任意名称规则。
- 句首名称插值要求后续字面量至少两个英文单词或 12 个非空白字符；句尾名称前的字面量至少 6 字符。过宽的 `^(名称) workspace$` 会把“Share workspace”误当实体名称。
- 实体名和类型名通过 `I18N_TERMS` / `i18nTerm()` 翻译，并把已知类型候选编进正则；未知类型应让后续规则继续处理。

## 4. 回归

先运行 `postman-zh.bat test` 的固定语料和保护用例，再按 [升级与发布](./升级与发布.md#2-发布前检查) 对比本轮新抓取的官方资源及相关反馈原文。固定样例通过不代表新增远端语料已经覆盖；无需额外运行已移除的巡检或缓存扫描工具。
