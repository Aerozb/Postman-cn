# 跨站子帧（OOPIF）汉化

> `AGENTS.md` 规则 6 的正文。**改 `payload/zh-oopif-inject-main.js`、动注入白名单、或怀疑某个 iframe 没翻之前必须读完本文件。**

## 1. 问题：preload 到不了独立进程的子帧

运行时翻译器一直靠 preload 注入（`Patch-Preload`）。preload 只作用于**同一个渲染进程里的 frame**：Chromium 站点隔离下，跨站 iframe 会被放进独立的渲染进程（out-of-process iframe，简称 **OOPIF**），preload 到不了那里。

`payload/zh-localize.js` 里的 `walkSameOriginIframes` 也帮不上：它靠 `frame.contentDocument` 取文档，跨源直接抛异常。所以 OOPIF 里的英文文案，**preload 和运行时遍历两条路都覆盖不到**。

这不是猜测。2026-09-11 用与 Postman 12.27.5 完全同版本的 Electron（37.10.3 / Chrome 138.0.7204.251）做了实测，实验代码在 `_generated/oopif-exp/`。

## 2. 四条候选路径的实测结果

实验用 `127.0.0.1` 主页嵌 `localhost` 子帧构造真实 OOPIF（两个不同 site，Chromium 会拆进程）。**先确认它真是 OOPIF**：主帧 `processId=4`，子帧 `processId=5`，不同进程。这一步不能省——同进程 iframe 里 preload 本来就能跑，不确认进程号会得出完全相反的结论。

| 路径 | 主帧 | OOPIF 子帧 |
|---|---|---|
| `webPreferences.preload` | 生效 | **进不去**（标记读回 `null`） |
| `webFrameMain.executeJavaScript` | 生效 | **能进** |
| `webContents.on('frame-created')` | 触发 2 次，但 `url` 为空 | 拿不到导航后的 frame，不能单独用 |
| `debugger` + `Target.setAutoAttach` + CDP | 主 target `Page.enable` **超时** | 能进 |

**选 `webFrameMain.executeJavaScript`，不用 CDP**，两个原因：

1. CDP 路径实测不稳，主 target 的 `Page.enable` 会超时。
2. 更要紧的是 `wc.debugger` **同时只允许一个客户端 attach**。占用它会直接和 `scripts/audit/` 下那 11 个 CDP 审计脚本冲突——审计是本项目发现漏翻的主要手段，不能为了几个 iframe 把它废掉。

第二轮实测把**真实的** `zh-localize.js`（2.3 MB）注进跨站子帧，确认端到端可用：文本节点、`title`、`aria-label` 全部翻译；子帧内部 600ms / 1800ms 后异步插入的文案也被翻译（`MutationObserver` 在 OOPIF 里正常存活）；子帧刷新后靠 `did-frame-navigate` 再注入一次即可恢复。

## 3. 实现

`payload/zh-oopif-inject-main.js`，由 `Patch-OopifInjection` 拷进 asar 的 `js/` 并在 `main.js` 顶部 `require`，走 `Patch-VersionCheck` 已验证过的「独立文件 + 注入处 require」路子。词典仍只有一份数据源——注入的就是 preload 用的同一个 `zh-localize.js`。

关键设计点，改代码时别改坏：

- **`did-frame-navigate` 是主要注入时机**。它对**子 frame** 也触发，而 `dom-ready` 只管主 frame。实测每次子帧导航（含刷新）都触发，时机足够早，首屏文案就已是中文。
- **只注跨进程子帧**（`isOutOfProcess` 比对 `processId`）。主帧和同进程子帧已由 preload 覆盖，重复注入虽被 payload 自身的 `__POSTMAN_ZH_LOCALIZER__` 守卫拦住，但那要先把 2.3 MB 源码传过去，白花开销。拿不到 `processId` 时保守注入——多注一次比漏翻好。
- **`frame-created` 只作兜底**，不直接注入（那时 `url` 实测为空）。
- **失败一律只 `warn`**，绝不影响 Postman 启动或主帧汉化。这是纯增量补充。

## 4. 白名单必须用真实域名，不能凭印象写

`ALLOWED_HOST_RE` 决定往哪些站点注入，写窄了漏翻、写宽了把脚本送进第三方页面。

**域名清单要从运行中的 Postman 的 CSP `frame-src` 里取**。2026-09-11 实测取到的 Postman 自有域是：

```
*.postman.com  *.postman.co  *.getpostman.com  *.cdn.postman.com  www.postman.com
*.pstmn.io     （dl-preview-container / client-proxy / skills-assets
                / flows-assets / runtime-assets 都在这个域下）
connect.us.integrations.postmancloud.com
```

最早只写了 `postman.com|postman.co|getpostman.com`，会把 `*.pstmn.io` 和 `postmancloud.com` 这两类**真实存在的 Postman 子帧**挡在外面——那正是要覆盖的目标。这个 bug 是端到端实测时看 CSP 报错才发现的，隔离回归发现不了。

**刻意不含 `js.stripe.com` / `hooks.stripe.com`**：那是第三方支付页面，既不该翻译，也不该由我们注入脚本。

## 5. 怎么验证（两层，缺一不可）

**第一层，隔离回归**：`scripts/runtime/验证跨帧注入.js`，由 `verify` / `install` 自动调用。Electron 和 fs 全用内存桩，不启动窗口、不读真实 payload。覆盖白名单边界（后缀伪装 `notpostman.com`、用户名段伪装 `https://postman.com@evil.com/`、域名出现在路径或查询里）、只注跨进程子帧、重复注入去重、失败只 warn。

**第二层，端到端实测**：只有这层能证明运行时真的生效。做法是连 CDP 往运行中的 Postman 页面插一个真实跨站 iframe，读回它的文本看是否变中文。

两个坑：

- **CSP 会拦掉本机探针**。Postman 页面的 `frame-src` 只放行上面那批自有域，插 `http://127.0.0.1:xxxx/` 会被拒（控制台报 `Refused to frame ...`，frame 树里留下 `chrome-error://chromewebdata/`）。解法是用 CDP `Fetch` 拦截，把白名单内的真实域名（如 `client-proxy.pstmn.io`）就地兑现成探针页面——既满足 CSP，又是真正的跨站 OOPIF，且请求不出网。不要改 hosts，那是系统级改动。
- **判别条件要干净**。该 iframe 与 `desktop.postman.com` 跨源，`walkSameOriginIframes` 拿不到它的 `contentDocument`，所以**内容一旦变中文，就只可能是主进程注入生效**。同源 iframe 做不了这个判别。

## 6. 一个教训：隔离回归全过 ≠ 真的能用

2026-09-11 第一次装完，`install` 和 `verify` 全部通过、24 项隔离回归全过，**但端到端实测是 FAIL**：真实 OOPIF 出现了，`hasLocalizer: false`，文案全是英文。

根因是 `main.js` 里的钩子写的是 `require("./js/zh-oopif-inject-main.js").install(E)`——传的是**整个 `electron` 模块**，而 `install(app)` 期望的是 `app` 对象。于是 `app.on("web-contents-created", ...)` 从没注册成功，异常被 `try/catch` 静静吞掉，**日志里连报错都没有**。

隔离回归漏掉它，是因为测试桩全都直接传 `app`，从没模拟 main.js 钩子的真实传法。修法是让 `install` 同时接受两种传法，并补一条专门复现真实调用方式的用例。这条用例做过**回滚验证**：撤掉修正后它确实失败（`1 !== 0`），恢复后 26 项全过——新加的测试必须这样验一次，否则不知道它到底有没有在测东西。

另外，Postman 的 `desktop_error.log` 里那条堆栈会把无关错误（读 `settings.json` 失败）安在 `zh-oopif-inject-main.js` 上，**是错误归因，别照着它查**。它只能说明这个文件确实被 `require` 了。

## 7. 已知边界

- **`audit all-targets` 能审计 OOPIF ≠ 翻译器能进去**，这是两件事：前者走 CDP 从外部附加，后者要往里注入脚本。现在主进程注入这条路通了，但仍受白名单约束。
- **canvas 绘制的文本翻不了**，跟 frame 无关。
- **白名单外的第三方 iframe 刻意不翻**（如 Stripe 支付页）。
- 横幅类界面由服务端随时下发新文案，注入机制通了不等于词条齐了——补词条仍走 `AGENTS.md` 第 5 节那套闭环。
