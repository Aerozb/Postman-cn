# 跨站子帧（OOPIF）汉化

修改 `payload/zh-oopif-inject-main.js`、白名单或排查跨站子帧时阅读本文。

## 注入路径

在 Postman 12.27.5 所用 Electron 37.10.3 的隔离实验中，普通 preload 未进入独立进程子帧；同源 iframe 遍历也受跨源访问限制。当前因此使用主进程 `webFrameMain.executeJavaScript` 注入同一份 `zh-localize.js`，不依赖占用应用 debugger 的注入方案。

安装器将模块复制到 asar 的 js 目录，并在 main.js 调用 `install`。该接口兼容传入 Electron 模块或 app 对象，测试必须覆盖真实安装钩子的传参，而不只测理想化的桩调用。

## 生命周期

- `did-frame-navigate` 是主要注入时机，支持子帧导航和同址刷新；`dom-ready` 只对应主帧。
- 仅针对跨进程子帧；主帧及已由 preload 覆盖的同进程帧跳过。读取进程标识抛错时保守尝试，避免漏翻。
- `frame-created` 时 URL 可能为空，仅用作延迟兜底。同一 webContents 合并兜底扫描，按当前文档代次去重在途/成功注入；导航重置状态，失败保留重试机会。不要单按 URL 去重，否则同址刷新会失效。
- 销毁窗口或 frame 后释放状态和延迟任务。失败只 warn，不让子帧补充功能破坏 Postman 启动或主页面。

## 白名单

实际实现允许 Postman 自有站点家族：`postman.com`、`postman.co`、`getpostman.com`、`pstmn.io`、`postmancloud.com` 及其子域；通过 URL 的 hostname 边界匹配，不按任意字符串包含判断。

升级时检查当前 Postman CSP 的 frame-src 和实际 iframe 来源，再决定是否调整白名单。历史上 `*.pstmn.io` 的工具页和 `connect.us.integrations.postmancloud.com` 都出现过，不应只凭品牌主站域名推测范围。Stripe 等第三方支付域刻意排除。

## 两层验证

**离线回归**由 `test`、`verify`、`install` 调用：真实安装钩子、域名伪装、同进程跳过、创建/导航组合、去重、同址刷新、失败重试、销毁与警告行为均使用内存桩。

**实机验证**用于确认 Electron 真正执行了注入：

1. 创建受控子帧，确认它与主帧的进程 ID 不同，不能用普通同进程 iframe 代替。
2. Postman CSP 通常排除本机探针。可通过 CDP Fetch 精确匹配一个白名单内的测试 URL，兑现为本地生成内容；首个导航在父目标拦截，子帧建立后也在其自身 CDP 会话启用相同拦截，保证刷新仍在本地兑现。测试内容不加载外部资源；结束后解除两侧拦截并删除测试 frame，不改 hosts 或系统网络配置。
3. 检查文本、title、aria-label、异步插入内容以及刷新后的翻译。跨源 contentDocument 不可读，因此跨源子帧中的翻译可证明主进程路径生效。
4. 离线用例通过不代替这层检查；尤其要验证 main.js 的真实 require/install 调用方式。

进程证据可用 `-*,blink.user_timing` 的短 trace（`ReturnAsStream`）：主/子帧各写入并清理自有 `performance.mark`，将对应事件的 PID 与 `SystemInfo.getProcessInfo` 的 renderer 核对。原始 trace 只留内存，报告仅保存测试标记关联的 PID 和验证结果。

## 覆盖边界

通过 CDP 读取子帧和生产注入是否生效是两件事。移除辅助探测脚本不影响本模块；注入只进入白名单站点，远端新文案仍通过官方 i18n 和截图反馈补齐。

运行时已挂接 Canvas 2D 的 `fillText`、`strokeText` 和 `measureText`，对实际文本走翻译并保留已知字段标识。这不覆盖现成位图、WebGL 或其他非文本绘制路径；也不代表画布有完整 DOM 上下文可供诊断。
