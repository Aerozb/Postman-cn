# 维护指南

普通用户看 [README](../README.md)。本文只保留维护闭环；命令与菜单见 [脚本说明](../scripts/README.md)，升级和发布见 [升级与发布](./升级与发布.md)。

## 日常工作

所有能力从根目录 `postman-zh.bat` 调用。菜单任务结束后手动回车关闭；CLI 直接返回退出码。

```powershell
.\postman-zh.bat test                 # 离线回归，无需启动 Postman
.\postman-zh.bat merge --check        # 预览 _generated/trans-*.json 可合并条数
.\postman-zh.bat merge
.\postman-zh.bat install             # 从原版重建、安装、启动并验证
```

一次性脚本和语料放在仓库同级 `_generated`。它可随时重建，不应成为固定命令的依赖。`test` 的固定回归与官方完整语料回归是两件事：前者保护已知行为，后者发现远端新增文案及更广的译文回退。

## 发现并补词条

维护只保留两条主线：**当前官方 i18n 批量补齐**，以及**用户截图反馈定点修复**。官方文件提供原文，实际界面仍由 `zh-localize.js` 运行时翻译，不是替换官方语言包。

- 批量维护或升级时重新抓当前官方资源，按 [官方 i18n 清单与生成规则](./官方i18n清单与生成规则.md) 展平、去重、测试已有翻译，再补固定文案或插值规则。
- 收到截图后先定位具体页面，必要时用 CDP 读取准确 DOM 文本、属性、空白和撇号码位。不要只凭截图猜词典键。
- 页面出现 `app-header:window_controls.close_win_tooltip` 或 `source_type_tooltip.jdbc` 一类未解析键时，将实际泄露的完整键作为 EXACT 兜底。

仅当上述两条未覆盖、或升级涉及本地页面时，再从缓存 bundle / 英文原版 asar 补查：关注 createElement 的字符串 children、JSX `children`、全大写标题和配套 JS 的 `text` / 三元表达式，别只抽属性形式字符串。本地兜底页包括 `html/desktop-offline.html`、`html/loader.html`、`html/auth/error.html`、`html/proxyAuth.html` 和 `html/no-scratchpad.html`。可在临时工作目录使用 `npx --yes @electron/asar extract-file <asar> <包内路径>`，不再维护固定缓存扫描命令。

先用权威 payload 的 `translate()` 检查候选。只翻完整标题、标签、句子；HTTP 字段、品牌、技术词、示例数据和半句碎片按 AGENTS 的边界保留。

译文 JSON 格式：`{ "English source": "中文译文" }`，命名为 `_generated/trans-*.json`。合并按最终 EXACT 查重，包含追加词典；归一键后验证新源码和每条实际译文，再写入。合并后仍应 `rg -F "中文译文片段" payload/zh-localize.js` 确认持久化，并再次 `merge --check` 确认没有重复新增。

## 定点检查与冒烟测试

```powershell
.\postman-zh.bat start
.\postman-zh.bat verify --details
```

`start` 会重启已运行的 Postman，确保调试参数生效。连接前读取新的 `DevToolsActivePort` 第一行；不要复用旧端口。

翻译器不再自动收集、保存或导出漏翻，也不读取、迁移或清理历史漏翻记录。MutationObserver、延迟重试、同源与跨站子帧注入仍负责动态界面的中文显示。

单条译文先用离线沙箱的真实 `translate()` 检查。涉及 DOM 行为时再通过 CDP 加入自有隐藏测试节点，等待 MutationObserver 和重试阶段完成后读回，结束时删除节点。临时脚本复用 `scripts/lib/CDP客户端.js`；报告经 `scripts/lib/诊断输出.js` 的 `writeDiagnosticReport` 保存，不落盘原始页面数据。截图按需显式采集，PNG 像素未脱敏。

## 半截翻译排查

本轮官方语料和反馈原文逐条过 `translate()`，挑出中文与普通英文混杂的结果；剔除代码、品牌和技术缩写后人工判断。运行时拼装文案只在对应反馈页面定点读取文本、属性和 shadow DOM，不把全界面遍历当固定前置步骤。

- PHRASES 兜底造成半译：优先补完整 EXACT，不放宽 `looksHalfTranslated`。
- EXACT/RULES 本身有半译：直接修正对应译文；这两条路径不经过半译闸门。
- 对比基线用 `git show HEAD:payload/zh-localize.js`，两版分别通过 `scripts/lib/汉化沙箱.js` 加载。列出“丢失已有中文”和“新增半截”的输入，不能只比较候选数量。

## 回归与安装确认

`test` 包括源码语法、文档链接、词典读取/合并、共享翻译样例、数据保护/调度、CDP/诊断输出、版本检查、跨帧注入，以及 PowerShell 入口/进程和发布预检的隔离测试。无需联网，不改真实进程或用户偏好。

`verify` 使用同一份固定翻译样例检查已安装实例，并验证 DOM 数据保护、组合文案、菜单及补丁标记；它不是全部远端语料的覆盖证明。改动后执行 `install`，再重走受影响界面。临时诊断的部分结果应明确标注，不等同完整通过。

安装器在原版上注入，验证成功才报告完成；替换正式 asar 后验证失败会尝试恢复英文备份。普通 `install` 不修改系统浏览器协议处理器；只有确认该配置有问题时，才使用 `fix-browser`。
