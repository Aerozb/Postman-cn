# 维护指南

面向维护者和贡献者。普通用户只需要运行根目录的 `postman-zh.bat`。

## 统一入口

普通用户双击根目录 `postman-zh.bat` 后使用中文 TUI。菜单提供 `install`、`verify`、`restore`、`start`、`stop`、`collect`、`static-scan`、`merge`、`audit`、`fix-browser` 和 `publish`；直接回车执行安装，`h` 查看帮助，`0` 或 `q` 退出。选中任务后只执行一次，收尾不等待按键，双击打开的窗口会自动关闭。

维护者和自动化也只从同一个根目录入口执行：

```powershell
.\postman-zh.bat help
.\postman-zh.bat install
.\postman-zh.bat restore
.\postman-zh.bat verify --details
.\postman-zh.bat collect --details
.\postman-zh.bat static-scan --disk
.\postman-zh.bat merge --check
.\postman-zh.bat probe
.\postman-zh.bat scan
```

`probe` 和通用 `scan` 是 CLI 专用维护能力，不在普通用户菜单中。入口内部按用途调用 `scripts\internal`、`scripts\audit`、`scripts\runtime`、`scripts\data` 和 `scripts\maintenance` 中的实现。不要直接运行内部文件，也不要再新增根目录 `.bat` 或转发用 `.ps1`。脚本目录的职责见 [scripts/README.md](../scripts/README.md)。

## 发布前检查

```powershell
Get-ChildItem .\payload,.\scripts -Recurse -File -Filter *.js | ForEach-Object { node --check $_.FullName; if ($LASTEXITCODE) { throw "JavaScript 语法错误：$($_.FullName)" } }
Get-ChildItem .\scripts -Recurse -File -Filter *.ps1 | ForEach-Object { [scriptblock]::Create((Get-Content -Raw -Encoding UTF8 $_.FullName)) | Out-Null }
.\postman-zh.bat help
.\postman-zh.bat install
git diff --check
```

安装脚本会在找不到补丁锚点时失败，不会假装安装成功。验证通过时必须看到：

```text
[Postman 汉化] 验证通过
```

安装时会先把 Postman 进程杀到清零，对修改后的 `main.js`、`preload_desktop.js` 和 `js/preload.js` 做语法检查，再替换正式 `app.asar`。运行时验证失败会自动恢复英文原版并清理本工具的临时文件。`restore` 也会先解包检查备份版本和干净标记。

普通 `install` 不修改系统 HTTP/HTTPS 处理程序。只有确认浏览器参数引号异常时，才显式运行：

```powershell
.\postman-zh.bat fix-browser
```

## 添加漏翻译

主要改 `payload\zh-localize.js`：

- 固定完整文案放入 `EXACT`。
- 可组合片段放入 `PHRASES`。
- 带数字、时间或名称变量的文案放入 `RULES`。
- 输入框默认值同时检查 `EDITABLE_EXACT`。
- 原生菜单词条改安装脚本中的菜单包装器，并且中文使用 `\u` 转义。

改完后运行：

```powershell
.\postman-zh.bat install
```

不要直接修改 `app.asar.unpacked.zh`，安装脚本每次都会从 `app.asar.original` 重新解包。

## 审计

审计脚本位于 `scripts\audit`，统一通过入口调用：

```powershell
.\postman-zh.bat scan --max-clicks 120 --delay-ms 180
.\postman-zh.bat audit lightweight
.\postman-zh.bat audit new-request --tabs docs,params,auth,headers --skip-final-sweep
.\postman-zh.bat audit new-collection
.\postman-zh.bat audit import
.\postman-zh.bat audit navigation
.\postman-zh.bat audit deep-areas
.\postman-zh.bat audit targeted-surfaces
.\postman-zh.bat audit entry-modals
.\postman-zh.bat audit phased --all-tabs
.\postman-zh.bat audit targeted
.\postman-zh.bat audit all-targets
```

TUI 的审计二级菜单按上面的 11 个 `audit` 名称提供中文选项；输入 `0` 返回主菜单。`scan` 是独立的通用交互扫描命令，不属于这 11 个审计名。

TUI 始终使用默认受控档。当前支持 `--thorough` 的审计名只有 `new-request`、`navigation`、`deep-areas`、`entry-modals`、`phased`、`targeted`、`targeted-surfaces` 和 `all-targets`。

| 审计 | 默认档 | `--thorough` 档 | 时间参数 |
|---|---:|---:|---|
| `new-request` | 降低交互次数、跳过响应历史 | 扩大交互并检查响应历史 | 无总审计时限参数 |
| `navigation` | 180 秒 | 900 秒 | `--audit-budget-ms` |
| `deep-areas` | 90 秒 | 600 秒 | `--audit-budget-ms` |
| `entry-modals` | 60 秒，跳过重量级全局搜索和通用入口遍历 | 300 秒，扩大入口覆盖 | `--budget-ms` |
| `phased` | 90 秒 | 600 秒 | `--audit-budget-ms` |
| `targeted` | 90 秒 | 300 秒 | `--audit-budget-ms` |
| `targeted-surfaces` | 90 秒 | 600 秒 | `--audit-budget-ms` |
| `all-targets` | 90 秒 | 600 秒 | `--audit-budget-ms` |

`new-request` 默认仍遍历当前请求类型的全部标签页；`--tabs` 用于主动缩小范围。`phased` 的 `--all-tabs` 与 `--thorough` 相互独立，只提高强度不会自动逐标签审计。各命令与内部中文脚本名的完整对应表见 [scripts/README.md](../scripts/README.md)。达到时间或扫描上限时会写出部分报告并返回退出码 `2`，发布前不能把它当成完整通过。

原生文件选择器不属于 CDP 页面审计范围。所有通用审计都必须跳过文件、文件夹、上传、浏览、选择文件和打开文件夹等入口；`targeted-surfaces` 也不应自行点击导入。导入弹窗只由 `audit import` 从 Postman 页面侧打开，它只遍历无需选择本机文件的页签，并必须在成功、失败或异常退出前清理自己打开的弹窗和临时菜单。

只把完整英文短语或混合未翻译片段当作问题；`GET`、`POST`、`API`、`HTTP`、`JSON`、`Git`、快捷键和产品名等技术词可以保留。

审计 JSON 统一由 `scripts\audit\审计安全.js` 脱敏后写入项目同级 `_generated`：URL 查询参数、WebSocket 地址、请求/响应正文、输入值、令牌和本机路径不会进入报告。新增审计脚本不得直接写原始 CDP 返回值；终端默认只显示中文摘要，排查时才显式加 `--details`。截图默认关闭；当前支持 `--screenshot` 的命令是 `probe`、`scan`，以及 `lightweight`、`new-request`、`new-collection`、`import`、`navigation`、`deep-areas`、`targeted` 审计。安全模块只限制 PNG 的输出位置和数据格式，不会脱敏截图像素，截图可能包含当前可见的工作区或请求内容，只应在本机安全环境中使用。

## 发布到 GitHub

发布脚本位于 `scripts\maintenance\发布中文版.ps1`，必须通过统一入口调用：

```powershell
.\postman-zh.bat publish -CheckOnly
.\postman-zh.bat publish -SkipRelease
.\postman-zh.bat publish -SkipRelease -Force  # 仅确认远程历史需要覆盖时使用
```

发布脚本会执行 `git add -A`、提交并推送；默认使用普通 `git push`，只有显式传入 `-Force` 才会强制覆盖远程 `main`。`-Yes` 只跳过确认，不会改变这个策略。发布前请确认 `app.asar` 已由统一入口重新打过汉化补丁。不要提交 `app.asar`、`app.asar.original`、`app.asar.unpacked.zh`、`_generated` 或带本机路径的审计产物。
