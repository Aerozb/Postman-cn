# 维护指南

面向维护者和贡献者。只想装中文版的话看 [汉化教程](汉化教程.md) 就够了。

## 发布前检查

```powershell
node -c .\payload\zh-localize.js
node -c .\payload\zh-auth-webview-preload.js
node -c .\scripts\verify-postman-zh.js
powershell -NoProfile -ExecutionPolicy Bypass -Command "[scriptblock]::Create((Get-Content -Raw .\scripts\install-postman-zh.ps1)) | Out-Null; 'PS_PARSE_OK'"
```

在本机 Postman 上完整安装并验证：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install-postman-zh.ps1 -Latest -DisableUpdates -Verify
```

`-Latest` 会按 `app-x.y.z` 版本号选择最高版本。不要只靠目录修改时间判断最新版本。

通用点击扫描：

```powershell
node .\scripts\scan-postman-clickables.js --out postman-click-scan --max-clicks 120 --delay-ms 180
```

如果只剩 `GET`、`POST`、`API`、`Git`、`Ctrl+K` 这类技术词或快捷键，通常不算漏翻。

新建请求全量审计很容易因为悬浮和右键数量太多而跑很久。维护时可以优先用 `audit-postman-new-request.js --tabs ... --skip-final-sweep` 分段检查基础标签、Body、脚本、设置、历史弹框，定位漏项后再跑全量。

## 添加漏翻译

主要改 `payload\zh-localize.js`。

- 固定完整文案：加到 `EXACT`。
- 可组合片段：加到 `PHRASES`。
- 带数字、时间、名称等变量的文案：加到 `RULES`。
- 输入框真实 value，例如 `New Environment`：同时确认 `EDITABLE_EXACT` 是否需要加入。
- 顶部 Electron 原生菜单：还要同步 `scripts\install-postman-zh.ps1` 里的 `postmanZhLocalizeMenuTemplate`，并且只能用 `\u` 转义，避免打包后的 `main.js` 编码问题。

改完后重新运行安装脚本。不要直接改 `app.asar.unpacked.zh`，因为安装脚本每次都会从 `app.asar.original` 重新解包。

## 更新禁用策略

`-DisableUpdates` 不删除 `Update.exe`，而是在 `main.js` 中打补丁：

- `g.isUpdateEnabled=false`
- `downloadUpdate(...)` 变为 no-op
- `restartAppToUpdate(...)` 变为 no-op

这样做的好处是不会破坏 Squirrel 快捷方式。缺点是 Postman 大版本改动后锚点可能变化；脚本会在找不到足够锚点时失败，而不是假装已经禁用。

## 外部浏览器链接补丁

安装脚本会在 `main.js` 顶部注入 `postmanZhPatchOpenExternalQuotes`，包装 Electron 的 `shell.openExternal`。这个补丁只剥离 URL 最外层成对的 `"`、`'`、`%22` 或 `%27`，不会改动 query 参数内部的编码引号。

`verify-postman-zh.js` 会检查 `externalUrlPatch.installed`，如果补丁没有写进 `app.asar.unpacked.zh\main.js`，验证会失败。

如果 `openExternal` 日志里 URL 已经没有引号，但 Chrome 地址栏仍出现引号，问题在系统 URL 协议处理器，不在 Postman。已见过的 VMware/ChromeGuestHTML 命令是：

```text
"C:\Program Files\Chrome\App\chrome.exe" --single-argument "%1"
```

这种情况下需要把 `"%1"` 改成 `%1`。`fix-browser-url-handler.ps1` 和安装脚本的 `-FixBrowserUrlHandler` 只会修复 `--single-argument "%1"` 这个明确模式，并会先备份原注册表命令。

## 版本兼容

当前已在 Postman 12.19.6 上验证（早前也验证过 12.12.2 / 12.12.3）。新版本如果失败，通常按这个顺序查：

1. `preload_desktop.js` 是否仍存在。
2. `main.js` 菜单锚点是否变化。
3. 请求标签右键菜单的 DOM 或 manager API 是否变化。
4. 新页面是否产生新的英文字符串。

## 发布到 GitHub

仓库：`Aerozb/Postman-cn`。发布用的脚本**故意放在仓库外面**（上一层的
`postman-zh-workspace\publish-postman-cn.ps1`），这样本机路径、账号等信息不会随仓库公开。

```powershell
..\publish-postman-cn.ps1 -CheckOnly              # 只做环境预检，不改任何东西
..\publish-postman-cn.ps1 -Force -ReplaceRelease  # 推代码 + 打包 + 重建 Release
..\publish-postman-cn.ps1 -SkipRelease            # 只推代码
..\publish-postman-cn.ps1 -SkipPush -SkipZip      # 复用已有压缩包，只重发资产
```

预检会检查 git / gh CLI 是否就位、gh 是否登录、token 有没有 `repo` 权限、
git 提交身份是否配好、对远程仓库有没有写权限、`app.asar` 是否真打过汉化补丁、
磁盘空间是否够打包。缺哪一项都会直接给出对应的修复命令。

凭据全部由 `gh` 自己管（keyring），脚本里不存任何 token。

### 不要提交的内容

- `app.asar`、`app.asar.original`、`app.asar.unpacked.zh` 等打包/临时产物
- `_generated/`、`nav-surfaces*.json`：审计与翻译过程的中间产物，体积大且对使用者无价值
- 任何用户数据、抓包记录、带本机路径的日志

以上都已写进 `.gitignore`。

### 词典里不要出现个人信息

翻译"当前用户"这类文案时，**不要把自己的账号名写成 `EXACT` 词条**。
曾经有过 `"某用户名 (you)": "某用户名（你）"` 这种硬编码，只对作者本人生效，
还会把账号名发到公开仓库。正确做法是写成 `RULES` 里的通用正则，用捕获组保留原名：

```javascript
[/^(.+?)\s+\(you\)$/i, function (_match, who) { return who + "（你）"; }],
```

发布脚本在打包前会扫一遍压缩包和 `app.asar`，发现本机路径或账号名就中止发布。
