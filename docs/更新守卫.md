# 更新守卫

修改更新拦截、更新页面或相关参数前阅读本文。

## 两个独立开关

| | Postman 自动更新 | 汉化版本更新检查 |
|---|---|---|
| 控制对象 | 官方升级，会覆盖汉化 | GitHub 汉化 Release 检查 |
| 默认及偏好缺失时 | 关闭 | 开启 |
| 用户目录内的偏好 | `postman-zh-updates.json` | `postman-zh-version-check.json` |
| CLI | `updates on/off` | `zh-updates on/off/check` |
| 实现 | 安装器注入 main.js 的守卫 | `payload/zh-version-check-main.js` |

两者都可能写自己的偏好文件。汉化版本检查只查询 Release 元数据、保存开关和忽略版本等偏好，**不下载或安装应用更新**。CLI 与页面共享各自偏好；JSON 使用无 BOM UTF-8。

## 官方更新守卫

统一入口默认向安装器传入 `-DisableUpdates`；`install -KeepUpdates` 则传入 false，表示不装守卫。这类实例独立验证时配套使用 `verify -KeepUpdates`。守卫存在时按偏好决定放行还是拦截，允许后调用已绑定保存的原实现。

- 保留 `isUpdateEnabled`，不要用它禁用整个更新服务，否则设置页会显示连接错误。
- 在主进程包装检查/安装入口，并将 `downloadUpdate`、`restartAppToUpdate` 改为条件分支。找不到已确认的锚点时安装失败，不假装成功。
- 偏好约缓存一秒；页面按钮经 `postman-zh:updates:get/set` IPC 读写。`verify` 检查守卫安装完整性，不要求用户的开关必须关闭。
- 页面开关单击切换。保留 `data-postman-zh-audit-skip="true"`，临时诊断也应跳过该元素，避免误改偏好。

## 页面定位与生命周期

更新页面随状态切换组件，`findUpdateToggleSlot()` 有三级定位：发布说明容器 `.settings-update-changelog-container`、旧版 `.settings-autoupdate`、更新状态按钮所在的设置内容区。每级都确认可见性，不能只判断节点存在。

两个开关放入同一个整宽 `#postman-zh-update-controls`。`stackedUpdateSlot()` 避开横向 flex/grid 包装，保留 Postman 原容器样式和已有按钮事件。定位排除本工具自己的面板，避免把自身当锚点。

设置切换页签后旧节点可能只是隐藏。每轮先 `removeStrayUpdatePanels()`，再决定是否插入；离开更新页就清理设置区。顺序颠倒会把刚删掉的面板立刻插回。

刚进入更新页时官方检查可能尚未完成，暂时没有锚点是正常状态。验证应轮询等待已知状态出现，并将页签选择限定在设置模态内，避免点到背后的工作区。

## 汉化版本检查

实现放主进程，避免依赖渲染页 CSP 的 `connect-src`。安装器复制独立模块，在 main.js 以短 require 钩子调用 `install(ipcMain)`。

本机兼容版本优先读 asar 的 package.json；CLI 场景回退到已发现的安装目录版本。Release 标签与兼容 Postman 版本对应；本机版本号不证明该汉化包已经发布。

查询必须确认公开稳定 Release、有效标签/时间，以及上传完成且大小大于零的两个匹配附件：`app.asar` 和 `Postman-cn-<版本>-win64.zip`。

| 状态 | 条件 |
|---|---|
| `latest` | 版本相同且附件齐全 |
| `update-available` | 远端更高且附件齐全 |
| `local-unpublished` | 本机版本高于最新公开版本 |
| `release-incomplete` | 附件缺失、空文件、上传未完成或 ZIP 版本不匹配 |
| `error` | 无效响应、未知本机版本、草稿/预发布等未确认情况 |
| `disabled` | 用户关闭检查，直接返回且不发新请求 |

启动、进入更新页、手动按钮及小时调度共用在途 Promise。普通缓存一小时，手动操作可刷新普通缓存；403/429 仍按 `x-ratelimit-reset` 退避，强制检查也不越过限额。完成后安排唯一的小时计时器，重复 run 不叠加。

关闭时禁用手动按钮，已发出的请求返回后重新核对状态，避免迟到结果恢复开关或弹出提示。页面约 900ms 的开关同步不重新请求 GitHub。网络故障不弹错误窗口、不显示“已是最新版”；设置页保留可诊断的状态。

提示条提供打开发布页、稍后提醒、忽略此版本。忽略操作保存 `dismissedTag`；更高版本仍可提示。打开链接由主进程固定目标，IPC 不接受任意 URL。

## 验证与升级边界

`test`、`verify` 和 `install` 运行版本状态及界面时序回归，使用内存网络、偏好和时钟。修改 UI 还需实机检查开关独立性、只在更新页出现、状态切换与按钮事件。

主进程 IPC 标记在独立模块里，不在 main.js；安装期临时 main.js 的交叉比对只能使用 `MAIN_JS_PATCH_MARKERS` 子集。

跨 Postman 版本只替换单个 asar 会与 Electron/原生模块不匹配。当前仅引导到发布页；升级应使用完整匹配包，再按 [升级与发布](./升级与发布.md) 安装。测试中的版本与附件组合也必须符合这一现实约束。
