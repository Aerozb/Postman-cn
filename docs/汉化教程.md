# Postman 汉化教程

本项目使用仓库根目录唯一入口 `postman-zh.bat`。普通用户只需要记住这个文件，不需要直接打开 `scripts` 目录。

## 环境要求

- Windows 10/11
- 已安装 Postman Desktop 12.x
- Node.js 22+（安装脚本需要 `npx --yes @electron/asar`，审计脚本使用 Node 内置 `WebSocket`）

## 安装

在 `Postman-cn` 根目录双击：

```text
postman-zh.bat
```

随后会显示中文交互菜单。输入序号选择操作，直接回车就是最常用的「安装汉化」，输入 `0` 退出；普通用户不需要打开 PowerShell，也不需要记任何命令。选择安装后会：

1. 自动选择本机最高版本的 `app-*` 目录。
2. 备份英文原版 `resources\app.asar.original`。
3. 注入汉化脚本并重新打包。
4. 关闭自动更新，安装应用内的外部链接兼容补丁，并启动验证。

普通安装不会修改 Windows 的 HTTP/HTTPS 处理程序。只有确认系统浏览器的 URL 参数引号异常时，才单独运行 `postman-zh.bat fix-browser`。

第 4 步「关闭自动更新」现在是**可以自己改回来的**。装完后 Postman 的「设置 > 更新」页最上面会多一栏「Postman 自动更新（汉化工具开关）」，想让 Postman 自动升级就点开它；主菜单第 `10` 项和 `postman-zh.bat updates on|off` 改的是同一个开关。注意开启后一旦升级成功，界面会变回英文，需要重新装一次汉化。

页面上是一个滑动开关，点一下即切换：向右橙色为「已开启」，向左灰色为「已关闭」。

流程结束后会直接自动关闭窗口，不再等待确认键；默认只显示简洁中文结果，不打印大段 JSON 或 Postman 内部日志。在 PowerShell 中带命令运行时则返回当前终端。

看到 `[Postman 汉化] 验证通过` 即表示安装完成。

## 中文菜单

| 序号 | 操作 | 适用场景 |
|---:|---|---|
| `1` | 安装汉化 | 首次安装、Postman 更新后重新汉化。 |
| `2` | 验证汉化状态 | 只检查当前安装是否完整。 |
| `3` | 还原英文原版 | 恢复自动备份的官方英文文件。 |
| `4` | 启动 Postman | 启动并等待审计所需的调试端口。 |
| `5` | 关闭 Postman | 彻底关闭全部 Postman 进程。 |
| `6` | 导出运行时漏翻 | 导出实际使用过程中记录的疑似漏翻。 |
| `7` | 静态扫描界面文案 | 扫描未翻译候选；菜单默认扫描运行中页面，维护者可用 `static-scan --disk` 扫描磁盘缓存。 |
| `8` | 合并译文 | 合并 `_generated/trans-*.json`。 |
| `9` | 深度审计界面 | 打开审计二级菜单。 |
| `10` | 自动更新开关 | 查看并切换 Postman 自动更新；默认关闭以保护汉化。 |
| `11` | 修复浏览器链接 | 仅在登录页外部链接异常时使用。 |
| `12` | 发布（维护者） | 推送代码并创建 Release。 |
| `h` | 查看完整命令帮助 | 显示维护者命令和参数。 |
| `0` | 退出 | 不执行操作；`q` 也会退出。 |

菜单会反复提示无效序号。选中一项任务后只执行一次，完成后自动关闭双击打开的窗口。“深度审计界面”中输入 `0` 返回主菜单，输入 `q` 直接退出。

审计二级菜单依次为：

1. 轻量界面巡检
2. 新建请求界面
3. 新建集合界面
4. 导入界面
5. 导航与设置界面
6. 深层界面
7. 容易漏翻的重点界面
8. 入口弹窗
9. 分阶段完整审计
10. 固定区域审计
11. 全部调试目标

以下命令行操作只供维护者、自动化测试或故障排查使用。指定版本目录或跳过验证：

```powershell
.\postman-zh.bat install -PostmanDir C:\Path\To\Postman\app-12.26.3
.\postman-zh.bat install -PostmanDir C:\Path\To\Postman\app-12.26.3 -NoVerify
```

## 还原

```powershell
.\postman-zh.bat restore
```

脚本会把 `app.asar.original` 恢复为 `app.asar`。如需保持 Postman 关闭，追加 `-NoRestart`。

## 验证与排查

`verify`、`collect`、`probe`、`scan`、全部审计，以及不加 `--disk` 的 `static-scan`，都要连 Postman 的调试端口，**Postman 必须在运行**；没开会报「没有找到 Postman 页面目标」，先跑 `start` 即可。菜单第 `1` 项「安装汉化」自己会重启 Postman，所以它内置的那次验证不受影响。

```powershell
.\postman-zh.bat start
.\postman-zh.bat verify
.\postman-zh.bat verify --details  # 仅排查问题时输出完整诊断
.\postman-zh.bat stop
.\postman-zh.bat fix-browser
```

运行时漏翻会由汉化器收集，导出清单：

```powershell
.\postman-zh.bat collect
.\postman-zh.bat collect -Clear
```

静态扫描和译文合并：

```powershell
.\postman-zh.bat static-scan --disk
.\postman-zh.bat merge --check
.\postman-zh.bat merge
```

更新页探测和通用交互扫描没有放入普通用户菜单，只供维护者从命令行调用：

```powershell
.\postman-zh.bat probe
.\postman-zh.bat scan --max-clicks 120 --delay-ms 180
```

审计脚本已经按用途放在 `scripts\audit` 下，通过入口选择，不需要记文件路径：

```powershell
.\postman-zh.bat audit lightweight
.\postman-zh.bat audit new-request
.\postman-zh.bat audit new-collection
.\postman-zh.bat audit import
.\postman-zh.bat audit navigation
.\postman-zh.bat audit deep-areas
.\postman-zh.bat audit targeted-surfaces
.\postman-zh.bat audit entry-modals
.\postman-zh.bat audit phased
.\postman-zh.bat audit targeted
.\postman-zh.bat audit all-targets
```

TUI 会使用默认受控档。发布前确需扩大覆盖时，维护者才在命令行加 `--thorough`；`phased` 要遍历所有已打开的请求标签还得单独加 `--all-tabs`（两者互不影响）。哪些审计名支持 `--thorough`、预算参数和默认时限见 [scripts/README.md](../scripts/README.md)。达到预算后保存的是部分报告，命令会返回退出码 `2`，不能当成完整覆盖。

自动审计不会点击“文件、文件夹、上传、浏览、选择文件”等会打开 Windows 文件选择器的控件。导入界面应单独运行 `audit import`；该命令只检查 Postman 应用内无需选择本机文件的页签，并在运行结束时自动关闭自己打开的弹窗和菜单。

完整命令和审计名称：

```powershell
.\postman-zh.bat help
```

所有审计产物默认写入仓库同级的 `_generated`，不会提交到 Git。JSON 报告会脱敏；截图默认不生成，只有一部分命令支持 `--screenshot`（名单见 [scripts/README.md](../scripts/README.md)）。得到的 PNG 可能包含当前可见的工作区或请求内容，截图像素不会被自动脱敏。

## 目录说明

```text
postman-zh.bat             唯一用户入口
payload\                   汉化词典和 webview 注入脚本
scripts\统一入口.ps1       命令分发器
scripts\internal\         安装、启动、停止等内部 PowerShell 实现
scripts\audit\            点击、悬停、右键等界面审计
scripts\runtime\          运行时漏翻收集和更新页探测
scripts\data\             静态扫描和译文合并
scripts\maintenance\      维护者发布脚本
docs\                      维护和汉化说明
```
