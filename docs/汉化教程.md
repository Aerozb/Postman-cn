# Postman 深度汉化教程

适用目标：Postman 桌面版 12.x，Windows 版。本包已在 Postman 12.19.6 上验证。

本汉化包会修改 Postman 安装目录里的 `resources\app.asar`，并自动保留原始备份 `resources\app.asar.original`。Postman 自动更新后通常会覆盖 `app.asar`，更新后重新运行安装脚本即可。

## 文件说明

- `payload\zh-localize.js`：汉化核心脚本，负责页面文字、输入框默认值、标题、属性、弹窗、右键菜单、标签右键菜单和应用菜单。
- `payload\zh-auth-webview-preload.js`：登录认证 webview 专用注入脚本，负责浏览器登录、授权令牌、登录失败/超时页面。
- `scripts\install-postman-zh.ps1`：一键安装脚本，负责备份、从原始备份解包、注入、打包、重启。
- `scripts\verify-postman-zh.js`：自动验证脚本，会连接正在运行的 Postman，检查主界面目标英文和标签页右键菜单。
- `scripts\audit-postman-lightweight-ui.js`：轻量工作台巡检脚本，会检查新建、导入、设置弹窗、请求页签、顶部菜单和底部栏。
- `scripts\audit-postman-new-request.js`：新建请求深度审计脚本，会逐项检查请求页签、下拉、右键和悬浮提示。
- `scripts\audit-postman-deep-areas.js`：全局角落深度审计脚本，会主动打开导入弹窗、新建菜单、设置页、侧边栏、底部栏、流程模块库、右侧面板，并检查悬浮提示和右键菜单。

## 一键安装

普通用户不用手动敲 PowerShell 命令，下载或解压后直接双击仓库根目录里的：

```text
install-latest-zh.bat
```

它会自动执行：

- 选择本机最新的 Postman `app-*` 版本目录。
- 备份原始 `resources\app.asar`。
- 注入汉化文件并重新打包。
- 禁用 Postman 自动更新，避免刚汉化完又被新版覆盖。
- 修复外部浏览器 URL 被引号包住的问题。
- 自动启动 Postman 验证汉化是否生效。

看到下面这一行就表示成功：

```text
[postman-zh] VERIFY PASSED
```

如果你是维护者，或者想指定某个版本目录，再使用下面的 PowerShell 命令。

把 `Postman-cn` 文件夹放到 Postman 安装目录的上级目录，例如：

```text
D:\Postman\Postman-cn
D:\Postman\app-12.19.6
```

在 PowerShell 里进入上级目录后运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\Postman-cn\scripts\install-postman-zh.ps1 -PostmanDir .\app-12.19.6 -Verify
```

如果不知道版本目录，先运行：

```powershell
Get-ChildItem -Directory -Filter "app-*"
```

也可以不写 `-PostmanDir`，脚本会优先使用当前正在运行的 Postman，或自动寻找最新的 `app-*` 目录：

```powershell
powershell -ExecutionPolicy Bypass -File .\Postman-cn\scripts\install-postman-zh.ps1 -Verify
```

如果你只想给最新版本安装，推荐使用 `-Latest`。脚本会按 `app-x.y.z` 的版本号选择最高版本：

```powershell
powershell -ExecutionPolicy Bypass -File .\Postman-cn\scripts\install-postman-zh.ps1 -Latest -Verify
```

## 推荐：安装并禁止自动更新

如果想避免 Postman 自动更新后变回英文，建议使用禁更新参数：

```powershell
powershell -ExecutionPolicy Bypass -File .\Postman-cn\scripts\install-postman-zh.ps1 -PostmanDir .\app-12.19.6 -DisableUpdates -Verify
```

也可以使用封装好的入口：

```powershell
powershell -ExecutionPolicy Bypass -File .\Postman-cn\scripts\install-and-freeze-postman-zh.ps1 -Latest
```

## 启动方式

安装完成后，正常启动 Postman 即可：

```powershell
.\Postman.exe
```

也可以直接启动已汉化的版本目录：

```powershell
.\app-12.19.6\Postman.exe
```

如果打开后又变回英文，大概率是 Postman 自动更新到了新的 `app-*` 版本目录，重新运行带 `-Latest` 的安装命令即可。

## 手动验证

安装脚本带 `-Verify` 时会自动验证。也可以在 Postman 已经用 `--remote-debugging-port=0` 启动后单独运行：

```powershell
node .\Postman-cn\scripts\verify-postman-zh.js
```

验证通过时会输出：

```text
[postman-zh] VERIFY PASSED
```

重点检查项：

- 主界面是否还有目标英文，例如 `New Environment`、`Untitled Request`。
- 请求历史空状态是否为中文。
- 主页固定引导、工作区列表、应用设置、证书、更新页面是否为中文。
- 标签页右键菜单是否为中文，例如 `复制标签页`、`强制关闭所有标签页`。

更深一层的点击扫描可以运行：

```powershell
node .\Postman-cn\scripts\scan-postman-clickables.js --out postman-click-scan --max-clicks 120 --delay-ms 180
```

扫描结果会生成 `postman-click-scan.json` 和 `postman-click-scan.png`。`GET`、`POST`、`API`、`Git`、`Ctrl+K` 这类技术词或快捷键保留英文不算漏翻。

专门深查“新建请求”窗口：

```powershell
node .\Postman-cn\scripts\audit-postman-new-request.js --out postman-new-request-audit --max-hover 220 --max-body-hover 90 --max-body-right-click 45 --max-right-click 140
```

脚本会自动点击文档、参数、授权、请求头、正文、脚本、设置，打开授权类型下拉和响应历史，并批量检查悬浮提示、右键菜单。正文页会逐个切换无、表单数据、x-www-form-urlencoded、原始数据、二进制、GraphQL，并检查这些模式里的悬浮提示和右键菜单。报告会生成 `postman-new-request-audit.json` 和 `postman-new-request-audit.png`。

如果全量检查在你的电脑上跑得太久，可以按模块分段跑：

```powershell
node .\Postman-cn\scripts\audit-postman-new-request.js --out postman-request-tabs --tabs docs,params,auth,headers --skip-final-sweep --skip-response-history
node .\Postman-cn\scripts\audit-postman-new-request.js --out postman-request-body --tabs body --body-modes none,form-data,urlencoded,raw,binary,graphql --max-body-hover 14 --max-body-right-click 6 --skip-final-sweep --skip-response-history
node .\Postman-cn\scripts\audit-postman-new-request.js --out postman-request-scripts --tabs scripts --max-scripts-hover 24 --max-scripts-right-click 10 --skip-final-sweep --skip-response-history
node .\Postman-cn\scripts\audit-postman-new-request.js --out postman-request-settings --tabs settings --settings-positions 0,0.5,1 --max-settings-hover 28 --max-settings-right-click 10 --skip-final-sweep --skip-response-history
node .\Postman-cn\scripts\audit-postman-new-request.js --out postman-request-history --tabs docs --max-hover 0 --max-right-click 0 --skip-final-sweep
```

轻量工作台巡检：

```powershell
node .\Postman-cn\scripts\audit-postman-lightweight-ui.js --out postman-lightweight-ui-audit --delay-ms 500
```

这个脚本更稳，适合快速复测新建、导入、设置弹窗、请求页签、顶部菜单和底部栏。报告会生成 `postman-lightweight-ui-audit.json` 和 `postman-lightweight-ui-audit.png`，`hitCount` 为 `0` 表示未发现非技术英文残留。

全局角落深查：

```powershell
node .\Postman-cn\scripts\audit-postman-deep-areas.js --out postman-deep-areas-audit --delay-ms 140 --overlay-hover 38 --overlay-right 16 --created-hover 20 --created-right 8 --settings-hover 38 --settings-right 12 --control-hover 12 --control-right 6 --new-menu-items 24 --import-items 18 --settings-tabs 14
```

这个脚本会先确保切到请求工作台，再逐个触发导入、新建、设置、侧栏、底栏、右侧面板、流程模块库等入口。报告会生成 `postman-deep-areas-audit.json` 和 `postman-deep-areas-audit.png`。

主页的远端帖子、公告、公开工作区内容属于在线内容，不建议强制汉化；API、HTTP、SSL、Cookie、Git、JWT 等技术术语也会保留。

## 还原英文原版

普通用户直接双击仓库根目录里的：

```text
restore-original.bat
```

维护者也可以关闭 Postman 后手动运行：

```powershell
$dir = "D:\Postman\app-12.19.6"
Copy-Item "$dir\resources\app.asar.original" "$dir\resources\app.asar" -Force
```

把 `$dir` 改成自己的 Postman `app-*` 目录即可。

## 能不能直接替换 app.asar

技术上可以，但不建议当成 GitHub 发布方式。

同版本、同平台、私下应急时，可以把已经汉化好的：

```text
Postman\app-版本号\resources\app.asar
```

复制到另一台电脑相同版本的：

```text
Postman\app-相同版本号\resources\app.asar
```

替换前务必先备份原文件。但这种方式有三个问题：

- 版本必须完全一致，12.19.6 的 `app.asar` 不保证能给 12.19.5、12.18.4、12.12.3 使用。
- `app.asar` 里面包含 Postman 官方完整程序代码，公开发布有版权和再分发风险。
- Postman 更新后会生成新的 `app-*` 目录，旧文件不会自动跟过去。

所以推荐给别人发这个文件夹，让对方双击 `install-latest-zh.bat`。它不是让用户自己研究脚本，而是让脚本自动识别最新版本、自动打包、自动验证；这样 12.18.4、12.19.6 或以后 12.x 新版本都按本机实际文件重新生成补丁，稳定性最好。

## 常见问题

登录时浏览器打不开：VMware 里需要允许“宾客机打开宿主机应用程序”，或者在虚拟机内安装可用浏览器并设为默认浏览器。安装脚本也会修复登录/授权页把外部链接传成 `"https://..."` 或 `%22https://...%22` 导致系统浏览器打不开的问题。

如果浏览器地址栏仍然带引号，问题通常在 Windows/VMware 注册的默认浏览器处理器。例如 `ChromeGuestHTML` 可能把命令注册成 `--single-argument "%1"`，Chrome 会把外层引号当成 URL 内容。可以运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\Postman-cn\scripts\fix-browser-url-handler.ps1
```

或者安装时加：

```powershell
powershell -ExecutionPolicy Bypass -File .\Postman-cn\scripts\install-postman-zh.ps1 -Latest -DisableUpdates -FixBrowserUrlHandler -Verify
```

直接运行 `Postman.exe` 还是英文：检查它实际启动的是哪个 `app-*` 目录，然后对那个目录重新运行安装脚本。

某处仍有英文：先运行验证脚本；如果验证通过但肉眼仍看到固定 UI 英文，记录具体入口、按钮或右键位置，把漏项加入 `payload\zh-localize.js` 的词典或规则后重新运行安装脚本。
